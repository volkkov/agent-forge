## Flagged as hype

- **kiki** — The repo is well-maintained by its timestamps (last push Nov 5 2026 is recent; non-archived; modest star count consistent with a niche product). But the provided README excerpt, particularly its feature descriptions, reads like product copy rather than a technical specification. There are no independent benchmarks, throughput figures, provenance traces for the headline WeChat/QQ bridging, or acceptance criteria that would let a reviewer verify any functional claim. That makes this "hype" rather than "broken": it has real infrastructure but unverifiable claims baked into the headline narrative.
- **unslop-skill** — The README gives a detailed, mostly accurate description of the architecture and flow, including MCP routing, version/checksum pinning, the detector's 37 checks with fixtures, and the mitigations when Node.js or the MCP SDK are missing — so the mechanism exists. However, every design finding and pass decision depends on the remote canon server, which is not self-hosted, not linked in the README as open source, and has no public endpoint-level verifiability; judging it from only this repo's perspective, it is hype disguised as useful because the core value proposition is unverifiable. A separate concern is the closed-backend risk: the README repeatedly emphasizes the private server and explains what happens when the canon cannot be reached ('no verified canon, no pass'), which is a sign of relying on an external service rather than fully self-contained infrastructure.
- **optics-framework** — The README describes an elaborate multi-platform test automation framework with six entry points (CLI, Python SDK, Robot Framework, REST API, terminal, MCP) and self-healing locators as its core selling point. However, no concrete mechanism is demonstrated in the provided excerpt — no example test file, no end-to-end test output, no benchmark of the 'self-heal' fallback strategy. The only concrete artifacts are install scripts and extras tables. Combined with 65 stars and a mid-2026 last-pushed date, the project appears live but has not yet accumulated benchmarks or user reports; the mechanism is asserted but not verified against runnable examples. A single sentence summary with this much broader capability implies marketing packaging rather than a focused product.
- **awesome-seedance** — The README is dominated by marketing language and lists example prompts without providing a concrete, step‑by‑step reproducible mechanism; it merely aggregates external content, which fits the 'hype' criteria even though the repo is actively maintained (last push 2026‑11‑05).
- **CORE** — The README is heavy on architectural diagrams and grandiose claims ('My personal definition of AGI is already satisfied', 'all-encompassing cognitive architecture') but shows no working demos, benchmarks, or installation verification. Only 16 stars and 5 forks after 2+ years suggests minimal community validation. The last-pushed date (2026-11-04) is in the future, indicating possible metadata issues. No evidence the system actually runs end-to-end.
