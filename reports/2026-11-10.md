## Flagged as hype

- **awesome-dsh-skills** — Evidence: 1) The README describes an *indexing and listing pipeline* (crawl from GitHub topics + full-text search, PR-driven curation, SKILL.md validation badge, daily-update Action workflow) but gives no reproducible recipe for generating entries or how any concrete DSH skill is built — just links into repositories and a 'no SKILL.md / ☑️ incomplete / ✅ valid' status table, which reads like curation artifacts not tool output. 2) The headline numbers ('1286 repos tracked, 770 passed') claim counts verified on the second day of November 2026 with a 'updated daily' note — but those figures are inventory metadata the viewer needs to trust; there is no independent verification methodology (beyond 'crawl + lint' which dsh-skill-lint itself provides). 3) No concrete product claims, benchmark results, or comparative numbers are in the excerpt; every entry line below the table just points at another repo — this is classic list-repo markup, not an engineering artifact. 4) CC0 license on the list itself is benign but irrelevant since this repo doesn't ship implementation. Verdict: marketing-flavored index, useful only as a navigation entry point with caveats.
- **max-cli** — This is essentially a thin client around a private vendor service (MAX, max.ru). The README’s redeeming concrete claims are real but isolated ('max personal inbox', 'personal review', 'MCP serve') while every paragraph is sample dialogue and design copy. Notably absent: benchmarks, changelog with IP protection claims, independent author list, and even minimal repro steps beyond `npx`. Vendor dependency is disclosed, and the npm package mirrors that, which is honest — but if you were hoping for generic corporate chat access it will deliver exactly what the vendor provides, with no safety net or interoperability advantage over native integrations.
