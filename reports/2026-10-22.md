## Flagged as hype

- **CIRISAgent** — 1) No concrete mechanism: The README is product-marketing copy (no config schema, no adapter protocol, no CLI flag table, no code sample beyond 'pip install ciris-agent'). 2) 'Coherence Ratchet' is a named academic paper with a DOI; this is plausibly real but unverifiable from the excerpt alone — and the README never states methodology, benchmarks, evaluator weights, or provenance, so the claim sits on buzzword without evidentiary grounding. 3) Press/app store banners imply consumer software; metadata says 'pip install ciris-agent', so if the package doesn't actually expose a runnable agent framework this is misleading packaging. 4) '(2025-04) Created' + 'Last pushed 2026-10-22' suggests >1 year of activity after creation, consistent with a real but small project, not a redirect to an abandoned fork. No missing archived, failing CI, or hidden crypto wallet/payment gate flags in the excerpt. Risk: AGPL-3.0 license claims alignment with 'open source'; article disclosure claims unverifiable.
- **Paragent** — The core mechanism (record→compile→replay with assertions, repair model fallback on failure) is concrete and well-documented. However the README itself discloses significant implementation gaps: the automated agentic recorder is explicitly not built (issue #127), the bundled demo gif is scripted rather than via the documented `npm run` commands, repair clients exist only as stubs (`StubRepairModelClient` proposes nothing) and have never been measured to actually self-heal live, and the long-tail docs (ADR files) are visibly partial. Combined with the CI org mismatch and only 13 stars/1 fork, this is hype for a repo whose 'record once, replay deterministicly' promise rests on scaffolding, not an shipped tool.


- **KESTREL** — The README only tells you to paste KESTREL.md as the system prompt (see Quickstart) and describes abstract layers, but never provides the actual prompt file or any reproducible demonstration; the text is filled with marketing buzzwords and unverifiable claims, so the mechanism is not concretely described.
- **bv-mcp** — The README describes a concrete mechanism (Cloudflare Worker host, Streamable HTTP JSON-RPC 2.0 spec, /health endpoint, explicit transport matrix with MCP-Session-Id header handling) — so this is not broken or undescued. But two features are unverifiable from the excerpt: the 81-tool count is actually 81 and 'zero install' is contradicted by every supported transport (stdio CLI, `claude mcp add`, legacy SSE), so the headline promise is partially misleading. More damningly: the CLAIMED 81 tools map onto roughly 38 named tool names in the README, and several described capabilities (Maturity staging 0-4, Trust surface analysis, Guided remediation artifact generation, self-tuning scoring via Durable Object telemetry, per-tier analytics, supply chain mapping) are either generic categories marketing already dumps into one page without evidence, or cloud/internal APIs not present behind this HTTP endpoint — yet they are sold as if always available. The BUSL-1.1 license and Ko-fi support badge are concrete risk flags for a real deployment; this is rebranded-BlackVeilY marketing for Black Veil Security.
- **claude-inspector** — The README describes a plausible local proxy architecture (local host interception, Anthropic API redirection) and provides structural detail on request tabs and session grouping mechanisms. However, the evidence provided for 'what Claude Code actually sends' rests entirely on self-generated traffic — the tool has not been independently audited and no third-party benchmark or replicable pipeline is described. The claims about per-request ~12KB CLAUDE.md injection sizes are presented as observed facts without any methodology, sampling depth, or statistical backing. No documentation of raw JSON handling beyond screenshot examples exists in the excerpt.
- **open-sesame** — The repo presents itself as a practical tool but the README excerpt is cut off before introducing any benchmarks, reproduction steps for engagements beyond basic clone/copy, or evidence of validated behavior. Without objective reproducible tests or performance data, claims about comprehensive coverage (Kerberoasting, BloodHound, Active Directory, container/Kubernetes, Wi-Fi) remain unverifiable and should be treated as descriptive content rather than proven capability.
