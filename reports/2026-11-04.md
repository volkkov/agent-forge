## Flagged as hype

- **Faraday** — README cuts off mid-list; single, self-reported latency figure on one benchmark phone; no CI, benchmarks, or test suite visible in the excerpt.
- **openamer** — The README excerpts feature an unusually large number of loosely-worded claims ('self-hosted', 'persistent memory', 'extensible tools', 'one heartbeat over 10 subsystems', 'replaces ~84 cron jobs') while saying nothing concrete about any of them: no architecture diagram, no dependency list, no example tool code, no wiring instructions. The project itself is a fork that appears to depend on Nous Research's Hermes Agent upstream; worth checking whether the upstream has diverged into an abandoned mid-hype state, but from the provided text alone it looks like a thin fork marketing shell around an upstream whose core mechanisms were not re-presented here. 'ASI modules', 'Mini-OpenAmer', and 'Darwin engine' are described as component names without benchmarks or reproducible mechanism; by the letter of the rubric this counts as unverifiable marketing framing.
- **finfocus** — The README clearly describes a concrete, reproducible mechanism — pricing `pulumi preview --json`, emitting PR comments via a GitHub Action, and a plugin-based architecture with real AWS public pricing (no billing access). The pinned release v0.3.3 and the live demo PR link provide support. However, the description overemphasizes buzzwords: 'shift-left on costs,' 'no code changes required,' 'world's most powerful' is absent but the framing remains general marketing ('cloud cost surprises are the norm'). Also notable: 'clean async/await' may be English phrase injected (possibly a parsing glitch), and there are no independent benchmarks; this leans toward 'hype' rather than confirmed useful.
